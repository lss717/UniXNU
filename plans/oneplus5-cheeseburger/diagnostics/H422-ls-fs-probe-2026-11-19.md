# H422 LaunchServices filesystem progress probe

Date: 2026-11-19

H421 showed that `lsd` was already inside
`+[_LSInstallProgressService beginListening]` when first sampled:

```text
LSServerMain
  -> beginListening
  -> performJournalRecovery
```

A second thread waited in `restoreInactiveInstalls` at
`dispatch_group_wait_slow`, while other workers were still enumerating system
content. The H421 open-only gate was therefore below the first observed state:
it could not distinguish filesystem latency from a dispatch-group dependency.

## Unique observation

H422 keeps all H421 behavior inputs and extends only the existing low-frequency
sampler gate. The instrumented operations are:

```text
open
read
write
fsync
getxattr
```

`NATIVE_LS_GATE` reports totals, in-flight count, slow counts at 50 ms, 500 ms
and 5000 ms, maximum latency and error count. Up to eight
`NATIVE_LS_GATE_SLOT` rows retain:

```text
op, tid, vnode, active, offset, requested, residual,
duration, result, bounded attribute name, bounded open path
```

The read/write path does not resolve a full path. It records the vnode and
operation parameters so it can be correlated with an earlier open. `getxattr`
copies only its bounded attribute name. All copies target fixed storage.

The completion helpers do not print, allocate, sleep, acquire a new lock or
change an IOReturn. Text output remains in the existing `lsd` sampler.
