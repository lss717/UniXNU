# H420 BKS timing and main-scene observer repair

Date: 2026-11-19

H419 established that the BKS main-screen request is delivered and receives a
reply whose id differs from the request id. It also exposed two observation
bugs:

1. the new context table always emitted `ctxfull`;
2. non-SpringBoard samples overwrote the BKS focus.

H420 addresses only those probes. It does not change AKS, display, CA scene,
Metal, IOSurface, IOMFB or scanout behavior.

## Context table fix

H419 initialized `index` and `free_index` to the table length. The scan selected
the first free slot in `free_index`, but the post-loop comparison was:

```c
if (index == free_index) index = free_index;
```

That never selected the free slot. H420 compares `index` with the table length:

```c
if (index == sizeof observed_contexts / sizeof observed_contexts[0]) {
    index = free_index;
}
```

The observer build marker changes to `H420`.

## Exact BKS focus

H419's `native_bks_focus_set` accepted the sampled message id from every
process. A containermanager sample therefore replaced the SpringBoard focus
with an unrelated id. H420 only changes the focus when the sampled id is
`0x5b9173`; a later SpringBoard sample with `msg=0` retains the original ports.

H420 also:

- records the receiver pid when the BKS request is selected from its queue;
- detects the reverse message from that responder to SpringBoard;
- records the response id and prints only records matching the request,
  response, reply port or responder;
- advances over nonmatching records without spending the 64-line output
  budget;
- stores `mach_absolute_time()` in each event slot and prints the exact event
  time in nanoseconds.

The IPC path still does not print, allocate, sleep or add a new lock.
